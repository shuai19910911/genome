# 2026-06-05 进度记录

## 本阶段已确认的规则

1. 作物范围使用“扩展栽培植物”。
   - 不只限于少数主粮作物。
   - 果树、蔬菜、油料、豆类、牧草、园艺作物等都可以纳入候选。

2. assembly 粒度改为“尽量收集当前作物所有已有基因组”。
   - 例如大豆中，`Zhonghuang13` 和 `Heihe43` 都应该下载。
   - 如果同一个 cultivar 或同一个 assembly 有重复来源，保留更合适的一份。
   - 去重时优先考虑来源可靠性、版本新旧、注释是否完整、是否有 GFF3/GTF。

3. 多来源冲突规则由脚本和人工审阅共同决定。
   - 优先公开、稳定、可复现的数据源。
   - 同一个 assembly 如果 Ensembl、NCBI、专项数据库都有，优先保留元数据更完整、注释更齐全的一份。
   - 如果不同来源代表不同 cultivar、不同 accession 或不同版本，则不直接合并，应先进入候选清单。

4. 注释格式尽量同时下载 GFF3 和 GTF。
   - 如果两者都有，候选清单要记录两者。
   - 如果只有一种，也可以进入候选，但要在 README 里写清楚。

5. 压缩格式保持来源 `.gz` 文件。
   - 不默认解压。
   - 下载后做 gzip 完整性检查和 SHA256。

6. 其他作物专项数据库已获批准使用。
   - 这些来源会进入候选来源范围。
   - 每个专项数据库需要记录来源 URL、版本、下载限制和备注。

7. Phytozome 先不下载。
   - 只记录“可能存在数据”和“后续再决定是否下载”。
   - 当前阶段不使用 Phytozome 作为实际下载源。
